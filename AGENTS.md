# Project Instructions

## Report planning gate

Before editing, regenerating, renaming, or replacing any group-report or individual-report source or deliverable, first record the proposed change in `BMMS2094_Group_and_Individual_Report_Plan.md`, Section 1.2, **Report change log**.

The proposed entry must state:

- the affected report or reports;
- the exact intended content change and its basis;
- the model, data, metrics, figures, citations, or conclusions affected;
- the files expected to change; and
- the validation required.

Check the proposal against the plan's fixed dataset, chronological split, four-model allocation, metric definitions, and current evidence before modifying a report. Apply only the recorded scope. After implementation, update the same log entry to `Applied and verified`, list the actual files changed and checks performed, and disclose any unresolved inconsistency.

If no matching proposed entry exists, do not change a report. Planning-file edits that introduce or update the entry are allowed and must precede report edits.

## Generated-report authorization

Do not regenerate, export, convert, replace, or otherwise update any report DOCX or PDF unless the user's current request explicitly mentions regenerating or updating the generated document. A request to edit report content, report planning, Markdown, analysis, or evidence does not by itself authorize DOCX/PDF generation.

When generation is not explicitly requested, modify only the recorded source or planning files, leave existing DOCX/PDF artifacts unchanged, and mark document generation and visual QA as pending in the report change log. When generation is explicitly requested, follow the version-archive policy and complete the required render and visual checks.
